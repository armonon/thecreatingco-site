What is Base64 used for?

Base64 encoding is a fundamental tool in web development, APIs, and data transmission.

🖼️
Inline images in HTML/CSS
Embed images directly in HTML or CSS as a data:image/png;base64,... URL, avoiding extra HTTP requests for small icons and thumbnails.
🔐
HTTP Basic Authentication
The Authorization: Basic header encodes username:password in Base64. This is standard HTTP authentication, though it should always use HTTPS.
📧
Email attachments (MIME)
Email attachments are encoded in Base64 to safely transmit binary files (images, PDFs, archives) over email protocols that only support ASCII text.
🔑
JWT tokens
JSON Web Tokens use URL-safe Base64 (Base64url) to encode the header and payload sections. You can paste a JWT header or payload here to decode it.
📦
API payloads
REST and GraphQL APIs often use Base64 to encode binary data (files, images) inside JSON bodies, since JSON is a text format and can't directly contain raw binary.
🛠️
Config and secrets encoding
Kubernetes secrets, CI/CD environment variables, and config files often store binary data or multi-line strings as Base64 to avoid formatting issues.

Frequently asked questions

What is Base64 encoding?
Base64 is a binary-to-text encoding scheme that converts binary data into a string of 64 printable ASCII characters (A–Z, a–z, 0–9, +, /). It is used to safely transmit binary data over channels that only support text, such as email, JSON payloads, and HTML attributes.
Does Base64 compress or encrypt data?
Neither — Base64 actually increases data size by approximately 33% (3 bytes of input → 4 Base64 characters). It is purely a text encoding, not a compression scheme. It is also not encryption — anyone can decode Base64 instantly. Never use it to protect sensitive data.
What is URL-safe Base64?
Standard Base64 uses + and / characters, which have special meaning in URLs. URL-safe Base64 (Base64url) replaces + with - and / with _ to make the string safe in URLs and filenames. JWTs use Base64url. This tool supports both — toggle the URL-safe option above.
Why does my Base64 string end with == or =?
Base64 encodes 3 bytes at a time into 4 characters. When the input length isn't a multiple of 3, padding characters (=) fill the remaining space. One = means 1 extra byte was padded; == means 2 bytes. Some implementations omit padding — both are valid.
How do I encode an image to Base64 for HTML?
Use the "File → Base64" tab above, upload your image, and click "Copy Data URI". The Data URI is the complete string to use in HTML: <img src="data:image/png;base64,...">. For CSS: background-image: url(data:image/png;base64,...);
Is this tool safe to use with sensitive data?
This tool runs entirely in your browser — no data is ever sent to any server. You can verify this by disconnecting from the internet and the tool will still work. That said, Base64 itself provides no security — do not Base64-encode passwords or confidential data and consider it protected.
What is the difference between UTF-8 and Base64?
UTF-8 is a character encoding that maps text characters to bytes. Base64 is a binary encoding that maps bytes to printable ASCII text. They serve different purposes: UTF-8 encodes human-readable text; Base64 makes arbitrary binary data (which may have already been UTF-8 encoded) safe for text-only channels.
