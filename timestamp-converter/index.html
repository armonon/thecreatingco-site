Frequently asked questions

What is a Unix timestamp?
A Unix timestamp is the number of seconds elapsed since January 1, 1970, 00:00:00 UTC — the "Unix epoch." It has no timezone component, so the same integer always refers to the same absolute moment regardless of where you are.
Seconds vs milliseconds — which do I have?
A 10-digit number is seconds (e.g. 1700000000). A 13-digit number is milliseconds (e.g. 1700000000000). JavaScript's Date.now() returns milliseconds; most Unix APIs return seconds. This converter detects both automatically.
How do I get the current timestamp in JavaScript?
Math.floor(Date.now() / 1000) → seconds. Date.now() → milliseconds. +new Date() → also milliseconds.
How do I get the current timestamp in Python?
import time; int(time.time()) → seconds. int(time.time() * 1000) → milliseconds. Python 3.3+: time.time_ns() → nanoseconds.
What is the Year 2038 problem?
Systems storing timestamps as 32-bit signed integers overflow at 2147483647 — January 19, 2038 at 03:14:07 UTC. After that, the value wraps to a large negative number. Modern systems using 64-bit integers are not affected. JavaScript uses 64-bit floats and is safe.
What timezone does a Unix timestamp represent?
None — a Unix timestamp is always UTC internally. When you display it as a human date you choose the timezone for that display. The same timestamp shows a different clock time in New York vs. Tokyo, but it always refers to the same instant.
What is the Unix epoch?
Midnight at the start of January 1, 1970 in UTC. The epoch itself has the timestamp value of 0. The date was chosen somewhat arbitrarily when Unix was designed in the late 1960s and early 1970s.
