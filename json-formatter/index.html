Common JSON errors to watch for

This validator will catch these — but knowing why they happen helps you fix them fast.

❝
Single quotes instead of double quotes
JSON requires double quotes everywhere. {'key': 'value'} is invalid JavaScript-style; {"key": "value"} is correct JSON.
⚠️
Trailing commas
JSON does not allow trailing commas after the last item in an object or array. [1, 2, 3,] and {"a":1,} are both invalid JSON.
🔑
Unquoted keys
Unlike JavaScript objects, all JSON keys must be double-quoted strings. {name: "Alice"} is invalid; {"name": "Alice"} is correct.
💬
Comments not allowed
JSON has no comment syntax. // comment and /* block */ will cause a parse error. Strip all comments before validating or transmitting JSON.
∞
Invalid values
JSON only allows: strings, numbers, booleans (true/false), null, objects, and arrays. Values like undefined, NaN, Infinity are not valid JSON.
🔗
Duplicate keys
Technically valid JSON (parsers accept it), but duplicate keys produce unpredictable behavior. Most parsers use the last occurrence. Avoid duplicating keys in the same object.

Frequently asked questions

What is JSON?
JSON (JavaScript Object Notation) is a lightweight text format for storing and exchanging data. It uses human-readable key/value pairs, arrays, strings, numbers, booleans, and null. JSON is the most common data format for web APIs.
What is the difference between formatted and minified JSON?
Formatted (pretty printed) JSON adds indentation and line breaks to make it readable to humans. Minified JSON removes all unnecessary whitespace to reduce file size. Both contain the exact same data. Use formatted for debugging; use minified in production to reduce transfer size.
How do I fix a "Unexpected token" JSON error?
Paste your JSON here and look at the error message and line number. Common causes: single quotes (replace with double quotes), trailing commas (remove the last comma in the object or array), unquoted keys (add double quotes around them), or JavaScript-specific values like undefined (replace with null).
Is my data safe to paste here?
Yes — this tool runs entirely in your browser using the native JSON.parse() and JSON.stringify() functions. No data is sent to any server. You can verify this by disconnecting from the internet and the formatter will still work.
What is the difference between JSON and JSON5?
JSON5 is a superset of JSON that allows single-quoted strings, unquoted keys, trailing commas, comments, and multi-line strings — making it more like JavaScript object syntax. This tool validates standard JSON (RFC 8259). JSON5 files that use these features will show as invalid here because standard JSON parsers do not accept them.
Can I format JSON from an API response?
Yes — paste any raw API response (minified single-line or multi-line JSON) into the input. The tool re-parses and reformats it with consistent indentation. Switch to Minify mode to compact it back into a single line.
What indentation should I use?
2 spaces is the most common convention for JSON (used by most APIs and tools like Prettier). 4 spaces is common in Python-generated JSON. Tabs are sometimes preferred in codebases that use tab-based indentation. All three produce identical data — only the whitespace differs.
