When do you need URL encoding?

Any time a URL contains characters with special meaning, encoding ensures the data passes through correctly without breaking the URL structure.

🔗
Query string parameters
When building a URL with data in the query string (e.g., a search query containing spaces or & symbols), encode each parameter value to avoid breaking the URL.
🌐
API requests
REST APIs often require URL-encoded parameter values in GET requests. Encode values like access tokens, search strings, or date ranges before appending them to API URLs.
📧
mailto links
Email subjects and bodies in mailto: links must be URL encoded. Spaces, line breaks, and special characters in subjects like "Re: Meeting & Notes" must be encoded for the link to work.
🔍
Search URLs
Search engines and site search features use URL-encoded query strings. If you're building a search redirect or deep link with a specific query, encode the search term first.
🗺️
Maps and location links
Place names with spaces, commas, and special characters in Google Maps or other mapping URLs must be encoded. "123 Main St, New York" becomes "123%20Main%20St%2C%20New%20York".
🛠️
Debugging encoded URLs
When you encounter a URL full of % sequences and need to read it, paste it into the decoder to get the readable original. Useful for debugging API responses or log files.

Frequently asked questions

What is URL encoding?
URL encoding (percent encoding) converts characters that are not allowed or have special meaning in a URL into a safe format using % followed by two hex digits. A space becomes %20, an ampersand becomes %26. This ensures the URL remains valid and the data is not misinterpreted as URL structure.
What is the difference between encodeURI and encodeURIComponent?
encodeURI encodes a full URL but preserves structural characters like /, ?, :, #, and @. encodeURIComponent encodes everything except letters, digits, and - _ . ! ~ * ' ( ), making it suitable for values inside query strings. Use encodeURIComponent (the "Query string" mode) for parameter values, and encodeURI (the "Full URL" mode) only for whole URLs.
Why does a space sometimes appear as + rather than %20?
The + encoding for spaces comes from the HTML form encoding standard (application/x-www-form-urlencoded), used when browsers submit HTML forms. The modern RFC 3986 standard uses %20. This tool uses %20, which is safe in all contexts. If your target system expects + signs, replace %20 with + after encoding.
When should I encode a full URL vs. just a parameter value?
Encode a parameter value (use "Query string" mode) when you're adding data inside a URL — e.g., the search term in ?q=hello+world, or a redirect URL in ?return=https://.... Encode a full URL (use "Full URL" mode) only when the entire URL string itself is a value being embedded somewhere else. For most use cases, query string mode is what you need.
Is my data sent to a server when I encode or decode?
No — encoding and decoding happens entirely in your browser using JavaScript's built-in encodeURIComponent, encodeURI, decodeURIComponent, and decodeURI functions. Nothing you type or paste is sent to any server.
What characters must be percent-encoded in a URL?
Characters that must be encoded include: space, ", <, >, {, }, |, \, ^, `, and any non-ASCII characters (accented letters, emoji, etc.). Characters like ?, &, =, #, /, :, @, and + have special meaning in URLs and must be encoded when they appear as literal values in parameter data rather than as URL structure.
Can I decode a whole URL at once?
Yes — paste the entire URL and click Decode. All %XX sequences in the URL are decoded at once. This is useful for making an encoded URL readable, debugging API responses, or converting log file URLs back to their original form.
