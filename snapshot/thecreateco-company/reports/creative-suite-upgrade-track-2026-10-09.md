# Creative Suite upgrade track — 2026-10-09

## Honest position

The suite is not meaningfully measurable as “N% from perfection.” The four
flagships are rich alpha products, but none has a fully qualified end-to-end
golden workflow. A passing local subset is useful engineering evidence, not a
claim that a creator can depend on the whole product without surprises.

The portfolio currently contains 46 registered products: 29 alpha, 9 prototype,
4 idea and 4 unknown-maturity entries. That breadth is a strength only if the
core workflows are dependable and cross-app handoffs are clear.

## Upgrade order

### 1. Make a creator's work safe before adding breadth

- ScenePilot: finish recovery for abrupt exit, disk pressure and missing media;
  then qualify import → edit → reopen → export on real media.
- Luma: resolve partial-alpha adjustment corruption, then qualify import through
  export and archive reopen.
- Form: qualify sketch-to-independent export and the full native/Fabric/
  Animation lifecycle.
- StemDeck: resolve captured replay scheduling and portable archive byte identity,
  then run a real perform → capture → replay → arrange lifecycle.

### 2. Make the suite feel like one product

- A consistent project/recent-work model, explicit unsaved/change/recovery state,
  and clear import/export handoffs across Form, Luma, StemDeck and ScenePilot.
- Locker integration must be proven as a workflow, not merely present as a menu
  item. Each handoff should say what is sent, where it is stored, and whether it
  remains editable.
- Normalize names, availability, feature states and Lite/Pro language. The
  already-queued ScenePilot UX task is the first concrete example.

### 3. Raise the professional bar

- Add performance budgets from real media/projects: launch, interaction latency,
  export time, long-session memory and failure behavior.
- Use UI polish only after the underlying state is reliable: dense-layout
  responsiveness, keyboard workflows, accessible labels, meaningful empty/error
  states, and undo/redo confidence.
- Establish release qualification on real user assets and supported platforms,
  not synthetic demos alone.

### 4. Add features against a workflow gap

Feature work continues, but every addition must name the workflow it completes,
the data-safety/recovery effect, and its performance budget. Current concrete
feature work already includes Form's pattern-first garment designer and WebLab's
visual composition/export prototype; neither substitutes for the flagship gates.

## Operating rule

For each product cycle: fix the largest proven workflow break → validate save/
reopen/export/recovery → improve clarity and speed → add the next feature. This
prevents a large feature catalogue from becoming a large set of fragile demos.
