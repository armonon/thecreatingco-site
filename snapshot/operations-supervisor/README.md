# Operations Supervisor

One hourly consolidated report to Discord `#maintenance` (`channel:1502117078763704320`). Sources are the live OpenClaw agent/session/cron catalog, recent automation run receipts, local Git worktree heads, and read-only company/marketing task counts. Discord channel sessions and cron destinations are discovered each run. No DM or raw transcript bodies are read or stored. A new channel first appears by stable numeric ID; add a friendly label in the one `config.json` registry when convenient. Product repositories are discovered under `repo_roots`, including worktrees outside that tree. Tracked uncommitted files are observed without falsely dating them or claiming completion.

Run `python3 supervisor.py report` for one report and `python3 supervisor.py daily` for a compact daily rollup. `python3 supervisor.py heartbeat ID --channel CHANNEL --status STATUS --task TEXT ...` allows an agent to update its local structured heartbeat after meaningful actions. Heartbeats supplement, never replace, independent evidence. `python3 supervisor.py channel CHANNEL --disable` opts a channel out; `--enable` restores it. `python3 supervisor.py channels` displays discovered registry rows.

Persistent SQLite: `data/supervisor.sqlite3`. Full reports: `reports/YYYY-MM-DDTHH-MM-SSZ.md`. Use a process lock to skip overlapping runs. Failed sources are isolated and marked unavailable. First report uses the prior 60 minutes; subsequent reports use the previous report timestamp. Retained hourly records support daily summaries. Model calls/tokens are counted only where automation receipts expose them; full provider cost is unavailable and never estimated.

Scheduled job: `Operations Supervisor hourly` (`8e672418-022e-4294-a77e-eb9fcaef28e8`), GPT-6 Luna with **no inherited premium fallback**, at minute 7 every hour, delivering once to `#maintenance`. Existing `#general` hourly digest remains unchanged. The supervisor has no Discord routing binding and does not receive ordinary channel messages. The collector locks out overlap. A separate five-minute **no-model** command job (`8e440556-6ef7-4099-aa9c-93a4175cc61a`) checks the configured public site, recent authentication/provider failures, and marketing's estimated spend; persistent critical findings alert after two observations and are deduplicated. It stays silent otherwise. A Gateway outage prevents Gateway-owned cron from running, so that one failure mode requires an independent host/external monitor if guaranteed out-of-band detection is needed.

For a new agent, add it normally to OpenClaw. Its Discord channel or cron destination is picked up automatically; the stable worker ID is `agent-id:channel-id`. For richer status, call the heartbeat command after meaningful transitions. To stop one channel, run `python3 supervisor.py channel CHANNEL_ID --disable`; other channels continue. To pause all reporting without deleting history, disable the two cron IDs above. All reports and the database are local; only the concise hourly text or true critical alerts go to Discord.
