A portfolio case study example that explains your contribution

A case study should explain the problem, your role and what changed. Concrete evidence is more useful than claiming that a polished image achieved an unspecified result.

Updated October 10, 2026 · by thecreatingco

Open Portfolio StudioApp overview & limits

A small example to work through

Our fictional example is a three-page workshop information site. The designer reorganised event details so the date, location and preparation list could be found together. No traffic or business result is invented.

Use the blank observation and decision fields to record your own result. These downloads are planning worksheets; they do not load an app project or demonstrate a completed export.

Try it and inspect the result

  1. Open Portfolio Studio and choose a small selection of work. For each item record the problem, your contribution and the evidence you actually have.
  2. Write a short narrative beside representative visuals. State whether a project is a concept, prototype or delivered work.
  3. Review the current export controls and open a saved result independently. Check image credits and links before sharing; an export does not itself host a website.

When the result differs

Case study lists only tools
Explain the decision made with each tool.
Outcome has no evidence
Describe the observed change or mark it as an intended result.
Images dominate on phones
Check the narrow layout and keep the main explanation readable.

What this example establishes

The example is fictional and the worksheet is not a Portfolio Studio export. It makes no claim of conversion gains. The public alpha needs an output and recovery check before a client delivery.

This page supplies a worked example and a review method. It does not report a newly completed end-to-end app test. For current availability and edition details, read the Portfolio Studio overview.
