How to keep HTML and CSS from a visual page prototype

A prototype is only recoverable if you keep its actual code. Test a very small page first and save both markup and styles before leaving the editor.

Updated October 10, 2026 · by thecreatingco

Open WebLabApp overview & limits

Prototype. No autosave or project reopening; keep a copy of your code before leaving.

A small example to work through

Our original prototype plan has a headline, a paragraph and one navigation link. The recovery record names two files and records which page structure the code should reproduce.

Try it and inspect the result

  1. Open WebLab and arrange a small set of blocks. Inspect the generated code and identify both the HTML and CSS portions.
  2. Copy the code into separate local files before leaving. Keep exact code rather than screenshots of the code pane.
  3. Open a saved copy and inspect text, links and layout. Repeat at a narrow viewport and check whether referenced assets also need to be saved.

When the result differs

Page opens without styling
Check the stylesheet link and relative file location.
Image works only in editor
Inspect the asset path and keep a permitted copy or durable URL.
Project vanished after leaving
The preview has no autosave or project reopening; saved code is your recovery route.

What this example establishes

The worksheet is not WebLab output or a deployment package. WebLab remains a preview and does not host a website. Its current generated-code editing has been checked previously, while download completion and persistent project recovery remain unqualified.

This page supplies a worked example and a review method. It does not report a newly completed end-to-end app test. For current availability and edition details, read the WebLab overview.
